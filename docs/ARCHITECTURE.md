# Документация Архитектуры: AI-ассистент для Telegram

## 1. Концепция и назначение
Система представляет собой персональный AI-слой поверх личного Telegram-аккаунта пользователя.
Авторизация осуществляется через пользовательский Telegram-клиент (**MTProto API** на базе Telethon).

### Режимы работы
1. **Только анализ (Analysis only)**: Читает сообщения, строит структурированную аналитику (intent, importance, urgency, topics, action items) и отправляет саммари в «Избранное»; ответы не отправляются.
2. **Предложение ответа (Draft reply)**: AI готовит черновик ответа, который попадает в очередь подтверждения (Human-in-the-loop). Пользователь может отредактировать текст и нажать «Одобрить и отправить».
3. **Автоответ доверенным (Trusted auto-reply)**: Автоматическая отправка ответов только проверенным контактам из белого списка при соблюдении детерминированных правил.
4. **Полный автомат (Full automation)**: Автоматическая обработка строго под контролем Rule Engine, Response Guard и Circuit Breaker.

## 2. Архитектура компонентов

```
Telegram Event (Telethon / Simulator)
       │
       ▼
Event Normalizer ──> Async Queue (Idempotency Key: chat_id + msg_id + action)
                           │
                           ▼
                     Message Worker
                           │
                           ▼
                  Deterministic Rule Engine (Priority 1-100)
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
        [Blocked / Ignored]         [Allowed]
                                         │
                                         ▼
                                  AI Analyzer (Strict JSON Schema)
                                         │
                        ┌────────────────┴────────────────┐
                        ▼                                 ▼
              Summary Service                   Response Generator
              (Instant alert / Digest)          (Limited context + style)
                        │                                 │
                        ▼                                 ▼
                «Saved Messages»                  Response Guard
                                                  (Leak & safety check)
                                                          │
                                            ┌─────────────┴─────────────┐
                                            ▼                           ▼
                                      [Draft Queue]              [Telegram Send]
```

## 3. Детерминированный Rule Engine
AI никогда не принимает единоличное решение об отправке. До вызова LLM выполняются детерминированные правила:
- **Приоритет 1**: Черный список контакта (`is_blacklisted`).
- **Приоритет 2**: Отключенный чат (`enabled = False`).
- **Приоритет 3**: Каналы Telegram (всегда read-only, автоответ запрещен).
- **Приоритет 4**: Пользовательские правила из БД по возрастанию приоритета (`priority`).
- **Приоритет 5**: Режим контакта (Whitelist / Draft / Analysis Only).
- **Приоритет 6**: Безопасный дефолт для незнакомцев (Только анализ, автоответ OFF, саммари при важности >= 8).

---

## 4. Response Guard и Безопасность
Перед любой фактической отправкой сообщения в Telegram (даже после одобрения пользователем):
1. Проверяется статус чата и белый список.
2. Проверяется лимит длины сообщения.
3. Проверяются опасные команды: бот-команды (`/start`), системные шелл-команды (`rm -rf`, `curl`, `bash`), SQL-инъекции.
4. Проверяется утечка секретов (API ключи `sk-`, JWT токены, токены ботов, приватные ключи RSA).
5. Проверяются запрещенные темы конкретного AI-профиля.
6. Проверяется отсутствие prompt injection артефактов.

---

## 5. Защита от спама и Circuit Breaker
- **Rate Limit**: ограничение на число ответов в минуту на чат и глобально.
- **Cooldown**: пауза между последовательными автоответами одному контакту.
- **Circuit Breaker**: при превышении порога ошибок или аномальном потоке сообщений предохранитель размыкается (`TRIPPED`), автоответы блокируются, и в «Избранное» отправляется предупреждение.
- **Privacy by Design**: шифрование Fernet AES-128 at rest, TTL для сырых сообщений, кнопка полного удаления всех данных.

---

## 6. Запуск и подключение Telegram
1. **Режим песочницы (Simulator)**: активен по умолчанию. Позволяет тестировать все сценарии без ввода реальных API-ключей прямо в веб-интерфейсе.
2. **Живой режим (Live Telethon)**:
   - Введите `api_id` и `api_hash`, полученные на [my.telegram.org](https://my.telegram.org).
   - Введите номер телефона и подтвердите кодом из Telegram.
   - Сессия шифруется и сохраняется локально.
